# 🎨 Satoshium Developer Documentation Style Guide

This style guide defines documentation standards for the Satoshium Developer Layer.

Its purpose is to ensure that developer-facing materials remain consistent,
clear, coordination-aware, and compatible with the broader Satoshium platform
architecture.

---

# 📡 Purpose

Developer documentation should support:

- vocabulary alignment
- registry compatibility
- governance awareness
- verification-friendly outputs
- simulation-layer clarity
- long-horizon maintainability

Documentation is treated as infrastructure rather than commentary.

---

# 🧭 Tone and Positioning

Satoshium documentation should remain:

- precise
- structured
- neutral in claims
- forward-compatible
- architecture-aware

Avoid marketing language, speculative claims, or unsupported capability statements.

---

# ✍ Writing Style

Preferred characteristics:

- short structured sections
- descriptive headings
- consistent terminology
- platform-layer awareness
- coordination-oriented explanations

Avoid:

- unnecessary abstraction
- informal naming of systems
- undocumented terminology
- implementation claims without references

---

# 📚 Vocabulary Alignment

Where possible, documentation should reference:

- canonical glossary definitions
- registry identifiers
- platform-layer terminology
- governance-aware interaction surfaces

Consistent vocabulary strengthens interoperability across systems.

---

# 🧱 Platform Layer References

When describing architecture, prefer standard layer references:

satoshium.ai architecture layer
satoshium.net infrastructure layer
satoshium.info knowledge layer
satoshium.xyz experimental layer
satoshium.dev developer layer


These mappings should remain stable across documentation surfaces.

---

# 🤖 Agent-Compatible Language

Documentation intended for agent-readable environments should:

- avoid ambiguity
- prefer structured terminology
- remain consistent across sections
- align with registry definitions where possible

This supports future coordination-aware tooling.

---

# 🔐 Governance-Compatible Documentation

Developer documentation should:

- avoid unsupported execution claims
- distinguish experimental systems from infrastructure components
- maintain transparency about system maturity
- preserve boundaries between layers

Governance clarity strengthens platform reliability.

---

# 🧪 Experimental vs Infrastructure Surfaces

Clearly distinguish between:

Experimental surfaces:

satoshium.xyz

Infrastructure surfaces:

satoshium.net

Developer coordination surfaces:

satoshium.dev

Architecture surfaces:

satoshium.ai

Knowledge surfaces:

satoshium.info

This separation preserves architectural clarity.

---

# 📐 File Structure Expectations

Developer documentation typically follows:

overview
purpose
role within platform
relationships to other layers
long-term direction
status


This structure supports readability and consistency across repositories.

---

# 🌐 Cross-Repository Consistency

Documentation within the developer layer should remain compatible with:

- satoshium-ai
- satoshium-net
- satoshium-xyz
- satoshium-info

Consistency across repositories strengthens coordination infrastructure.
